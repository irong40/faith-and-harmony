## 1. What changed from the Cost-Plus model

v2.0 priced jobs with flat package values (§3) and an implicit strict **Cost-Plus**
calculation: `hourly labor + fixed expenses`, then `+20% overhead`, `+10% depreciation`,
then a `40% margin`. That model leaves money on the table because it ignores
willingness-to-pay and the value of our airspace/authorization moat.

v2.1 moves to a **Hybrid Value-Based** model:

- The legacy Cost-Plus math is **retained**, but **only as the internal break-even
  floor** — it is "for our eyes only" and never reaches the client.
- The **client-facing quote** is generated by new business rules (below) that
  capture value rather than just recover cost.

## 2. Internal break-even (retained, internal-only)

```
labor_cost        = labor_hours * loaded_rate          # default loaded rate $85/hr
base_cost         = labor_cost + direct_expenses
overhead          = base_cost * 0.20
depreciation      = base_cost * 0.10
BREAK-EVEN FLOOR  = base_cost + overhead + depreciation
cost_plus_ref     = BREAK-EVEN FLOOR * 1.40            # legacy single price, reference only
```

- The **break-even floor** is the number we must never price below.
- `cost_plus_ref` uses 40% as a **markup over fully-loaded cost** (price = cost × 1.40).
  If true gross margin is intended instead, use `cost / (1 − 0.40)`. Flagged as an
  assumption — confirm which definition Finance wants; constant lives in one place
  (`COST_PLUS_MARKUP`).

## 3. Client-facing business rules

### 3.1 Monetize the airspace moat (Req 1)
Two manual toggles in the inputs section:

| Toggle | Line item added to client quote |
|--------|---------------------------------|
| LAANC Authorization Required | +$75.00 |
| CAPS / Zero-Grid Manual Authorization Required | +$250.00 |

Airspace fees apply across **all** quote modes (standard, day-rate, tiered).

### 3.2 Minimum call-out floor (Req 2)
For **residential** jobs: if the final calculated quote (cost-plus base + airspace)
is **under $350**, the engine raises a **UI warning** and bumps the recommended
minimum quote to **$350.00**. No residential job ever quotes below the call-out floor.

### 3.3 Commercial day rates (Req 3)
For **commercial unstructured** jobs (e.g., perimeter inspections), a **Day Rate
Pricing** toggle:
- Hides the hourly margin output from the client view.
- User selects a **Full Day Rate** from **$1,500 to $3,000** ($250 steps).
- **Half-Day Rate = 65% of Full Day Rate** (explicitly **not** 50%).
- Airspace fees (if any) add on top of the day rate.

### 3.4 Value-based tiered quoting for advanced data (Req 4)
For advanced analysis missions (volumetric stockpiles, thermal anomalies, 3D
photogrammetry), the engine computes internal cost but **outputs a 3-tier package
recommendation** instead of a single price:

| Tier | Base price | Deliverables |
|------|-----------|--------------|
| Basic | $800 | Raw data, Orthomosaic, Point Cloud |
| Pro | $1,800 | Basic + Measurements, Annotations, CAD exports |
| Enterprise | $3,500 | Pro + Change detection, Custom reporting, Priority turnaround |

Airspace fees add to each tier total.

## 4. UI/UX requirements (Req 5)

- Flet admin screen. Inputs section at top; outputs below a **2px divider**.
- Two clearly separated, color-coded containers:
  - **INTERNAL BREAK-EVEN COSTS** — red-tinted, lock icon, "FOR OUR EYES ONLY".
    Hourly breakdown lives **here only**.
  - **CLIENT-FACING QUOTE** — green-tinted. **Never** receives hourly figures.
- Minimum call-out and below-floor conditions render as amber warning banners.

## 6. Persistence (wired up June 9, 2026)

**Decision (CE4 resolved):** do **not** create a new `mission_quotes` table. The schema
already has `mission_costings` (legacy internal cost-plus record) and `quotes`
(client-facing). The engine persists to **`mission_costings`**, extended additively
with the hybrid value-based columns. This avoids duplicating two existing tables.

- **Project:** FaithandHarmonyAPP (`qjpujskwqaehxnqypxzu`) — the single Trestle Supabase
  instance (PRD §2.1). Mission table is `drone_jobs` (`mission_authorizations.mission_id`
  → `drone_jobs.id`).
- **Migration:** `add_hybrid_value_based_columns_to_mission_costings` — adds
  `mission_id` (FK → `drone_jobs`), `quote_mode`, `is_residential`, `laanc_required/fee`,
  `caps_required/fee`, `airspace_fees`, `break_even_floor`, `min_callout_floor/applied`,
  `recommended_quote`, `full_day_rate`, `half_day_rate`, `value_tiers` (jsonb), plus a
  `quote_mode` CHECK and an index on `mission_id`.
- **Field mapping:** labor → `pilot_rate`/`pilot_hours`; `direct_expenses` →
  `expenses_subtotal` (category columns 0); break-even → `total_expenses` /
  `break_even_floor`; cost-plus reference → `total_charge`; floor/below-floor →
  `surcharge_warning`; tiers → `value_tiers` jsonb.
- **Access:** writes use the **service-role key** (read from
  `processing-server/.env`), bypassing the `admins_manage_mission_costings` RLS policy.
  Internal desktop tool only — the service key must never ship to a client build.
- **Verified:** end-to-end insert → readback → delete passed via `supabase-py`
  (standard floor-bump case and value-tiered case).

**Not yet wired (next step):** "Convert to quote" — promote a saved costing into a
`quotes` row (`line_items` jsonb + `total` + `acceptance_token`) and back-link via
`mission_costings.converted_to_quote_id`.
